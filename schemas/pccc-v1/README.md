# PCCC ThingsBoard Data Contract V1

Authoritative implementation dictionary. Example fixtures are illustrative values generated by the real serializer, not hardware measurements. All telemetry is flat scalar; `event_` fields mirror the table for historical transitions. Native `ts` (milliseconds) wraps `values` only after trusted clock synchronization.

Measurement validity: Fresh/valid at capture; omitted if invalid/stale/non-finite; history retains original observation

Client attributes: firmware_version, build_id, config_id, hardware_model, zone_id, capabilities, reset_reason, schema_version, recommended_inactivity_ms. No shared attributes, RPC subscriptions, remote ACK or remote threshold control.

Quality enum VALID describes software acquisition/validation only. INITIALIZING, INVALID and STALE omit affected measurements. Missing keys do not erase ThingsBoard Latest values: operational widgets/rules MUST check current quality and capture age. Historical values use quality at original capture, not replay time.

`persistence_health`: PENDING=0, DURABLE=1, FAULT=2 (WP01). Per-boot diagnostic counters reset on reboot; physical_ack_seq is persistent WP01 history. Aggregate event_drop_count may overlap journal-copy failures and RAM rejection; it is not an exact distinct-event-loss count. No offline critical-record TTL: expiry count measures retry attempts, not silent history deletion.

Compatibility: producer schema is strict to catch accidental keys/types. Consumers gate schema_version, ignore documented optional unknown extensions and route TRANSITION separately. Breaking names/units/meaning require a new version. `event_*` is an intentional pre-release refinement from the baseline proposal: historical replay cannot overwrite unprefixed live risk even under default ThingsBoard timeseries saving. Phase 2 must adopt these names before new Cloud rules are enabled.
